# Fase 5 — Generador de ACLs: Plan de implementación

**Goal:** Modelo neutral de ACLs, importación desde Cisco IOS/IOS-XE, NX-OS y ASA, análisis de reglas sombreadas, redundantes e imposibles, y generación de texto para esas tres plataformas; expuesto por gRPC, `mctl` y una pantalla en la UI.

**Architecture:** `internal/acl` es lógica pura sin red: `model.go` (tipos y normalización), `parse.go` (importación por fabricante), `analyze.go` (cobertura entre reglas), `gen.go` (generadores). El núcleo solo traduce proto ↔ modelo. La UI importa texto, muestra hallazgos y genera; el editor visual con React Flow queda para después.

**Tech Stack:** Go 1.27, `net/netip`. Sin dependencias nuevas.

**Spec:** `docs/architecture/2026-11-02-macuahuitl-architecture-design.md` §13. Contrato: `api/proto/macuahuitl/v1/acl.proto`.

## Global Constraints

- Nunca se aplica nada a un equipo: la salida es texto (spec §13).
- Direcciones en el modelo como CIDR (`0.0.0.0/0` = any); puertos como rangos cerrados.
- Las máscaras wildcard no contiguas se rechazan al importar con error que nombra la línea.
- Solo IPv4 en esta fase.

## Review Focus

1. **Wildcard no contigua** (`10.0.0.0 0.0.255.0`) debe dar error con número de línea, no una regla inventada. Test en Task 2.
2. **Máscara ASA vs wildcard IOS**: `255.255.255.0` en ASA es /24; en IOS `0.0.0.255` es /24. Confundirlas invierte la red. Test en Task 2.
3. **`neq` y `gt 65535`**: `neq 25` son dos rangos; `gt 65535` es un conjunto vacío e imposible. Test en Task 1 y 3.
4. **Regla sombreada por una anterior con acción distinta** se reporta como `shadowed`; con la misma acción como `redundant`. Test en Task 3.
5. **Puertos con protocolo `ip`** son imposibles: IOS lo rechaza, el modelo también. Test en Task 1.

### Task 1: Modelo y normalización
**Files:** `internal/acl/model.go`, `internal/acl/model_test.go`
**Produces:** `type Action int` (`Permit`, `Deny`); `type PortRange struct{Lo, Hi uint16}`; `type Rule struct { Action; Protocol string; Src, Dst netip.Prefix; SrcPorts, DstPorts []PortRange; Log bool; Remark string }`; `type ACL struct { Name string; Rules []Rule }`; `func ParsePorts(op string, args ...string) ([]PortRange, error)` para `eq|neq|gt|lt|range`, con nombres (`ssh`, `www`, `domain`…); `func (r Rule) Validate() error` (puertos solo con tcp/udp, rangos no vacíos); `func ProtocolNumber(name string) (int, bool)`.

### Task 2: Importación
**Files:** `internal/acl/parse.go`, `internal/acl/parse_test.go`, `internal/acl/testdata/{iosxe,nxos,asa}.txt`
**Produces:** `func Parse(vendor, text string) (ACL, error)` con `vendor` ∈ `ios-xe|nx-os|asa`; `type LineError struct{Line int; Msg string}`. IOS: `ip access-list extended NAME`, `remark`, `permit|deny PROTO SRC [ports] DST [ports] [log|log-input]`, direcciones `any|host X|X WILDCARD`, numeradas `access-list N …`. NX-OS: `ip access-list NAME`, `[seq] permit …`, direcciones `X/len|host|any`. ASA: `access-list NAME extended permit …`, direcciones `X NETMASK|host|any|any4`, `access-list NAME remark …`.

### Task 3: Análisis
**Files:** `internal/acl/analyze.go`, `internal/acl/analyze_test.go`
**Produces:** `type Finding struct{Index int; Kind string; Detail string}` con `Kind` ∈ `shadowed|redundant|impossible`; `func Analyze(a ACL) []Finding`; `func (a Rule) Covers(b Rule) bool`.

### Task 4: Generación
**Files:** `internal/acl/gen.go`, `internal/acl/gen_test.go`
**Produces:** `func Generate(vendor string, a ACL) (string, error)`; ida y vuelta: `Parse(v, Generate(v, a))` equivale a `a` para las tres plataformas.

### Task 5: Servicio, CLI y UI
**Files:** `internal/core/services_acl.go` (+ test en `core_test`), `cmd/mctl/main.go` (`acl import|analyze|generate`), `ui/bridge/bridge.go` (`AclImport`, `AclAnalyze`, `AclGenerate`), `ui/frontend/src/modules/acl/AclView.tsx` (+ test), `App.tsx` (pestaña ACLs).
